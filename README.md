# PESU Wi-Fi sign-in helper

Small helper that signs your Mac into the **PESU hostel captive portal** (`https://rr.pes.edu:8090`)
automatically when you connect, and lets you run the same sign-in manually.

## What it does

- **Auto mode (launchd):** runs silently every 60 s, on login, and the moment the Wi-Fi network
  changes. Logic per run:
  1. Asks macOS' built-in captive probe (`http://captive.apple.com/hotspot-detect.html`).
     Reply is `Success` → already online → exit, do nothing.
  2. Confirms you're actually on the PESU network (`rr.pes.edu` must resolve to a private
     address and the portal must answer on `:8090`). Otherwise exit — credentials can never
     be sent to a foreign portal.
  3. Sends the **same** request the portal page's own JavaScript sends: a POST to
     `https://rr.pes.edu:8090/login.xml` with `mode=191&username=…&password=…&producttype=0`.
  4. Reads the answer and acts:
     - `LIVE` → signed in, banner notification.
     - `CHALLENGE` → one follow-up POST with the portal's own `state` token (max 2 POSTs).
     - device/session-limit message → tries the **fallback credential once**, then stops and
       tells you to sign out on the other device / contact `itteam.rr@pes.edu`.
     - any other rejection → stops, no retry loop.
- **Manual mode:** `--once` runs the same flow in your terminal with full output.

## Security properties

- Credentials live **only** in the macOS Keychain (services `pesu-wifi-primary` and
  `pesu-wifi-fallback`). Nothing is stored in this script, and **no password is ever written
  to a log**.
- The password (percent-encoded by `/usr/bin/perl`) is written to a `chmod 600` temp file and
  sent with `curl --data-binary @file` — so it never shows up in `ps`, shell history, or argv.
- The only destinations ever contacted are the portal (`rr.pes.edu:8090`) and Apple's captive
  probe (no credentials).
- **No retry loops, no credential guessing, no device-identifier (MAC) changes.**
  At most 2 POSTs read portal requests (`CHALLENGE`), and never more than one attempt per
  stored credential per run.

A launchd agent file `com.local.pesu-wifi.plist` is generated by `--install` and copied to

## How the pieces work (basic concepts)

- **Captive portal:** when a client is not authenticated, the network only lets it reach the
  portal (port 8090) and a few whitelisted check URLs. macOS' own check URL is
  `captive.apple.com`; an unauthenticated client gets rerouted, an authenticated one gets
  `Success`. That probe is our "do I need to sign in?" signal.
- **Keychain via `security`:** `security add-generic-password` stores a secret;
  `security find-generic-password -s <service> -w` reads it back without it ever hitting
  your files.
- **LaunchAgent:** a `~/Library/LaunchAgents/*.plist` that `launchd` (macOS' process
  manager) runs for your user. `RunAtLoad` runs it at login, `StartInterval` every 60 s and
  `WatchPaths` fires it when the network configuration changes.
- **The login transaction:** the portal page's JS posts `mode=191&username&password` to
  `login.xml` and reads `<status>` + `<message>` XML. This helper replays that exact request
  with `curl`, so the result and any "limit" wording it detects are the portal's own.

## Setup (do once)

1. Open **Terminal** (Spotlight → "Terminal").
2. `cd ~/pesu-wifi`
3. Save your credentials:
   ```
   ./pesu-wifi.sh --setup
   ```
   Enter your username, then your password (it is hidden while you type), and optionally a
   fallback ID used only when your main ID hits the device/session limit.
4. Check it can read everything:
   ```
   ./pesu-wifi.sh --status
   ```
   (Expect "connection : online" if you are already signed in.)
5. Turn on background auto sign-in:
   ```
   ./pesu-wifi.sh --install
   ```

That's it. To test the manual flow: `./pesu-wifi.sh --once`.

## Permissions / requirements

- **None beyond what Terminal already has.** This design deliberately avoids Chrome
  (no "Allow JavaScript from Apple Events"), System Events (no Accessibility), and any app
  bundle. The only system features used are Kernel→Keychain (`security`, prompts once if your
  login keychain is not the default), launchd (already allowed for `~/Library/LaunchAgents`),
  and the notification banner (respects macOS "Focus"/Do-Not-Disturb — if you see no banner,
  check Focus).
- macOS **27 (Tahoe+)**. Requires the built-in `curl` (with TLS), `perl`, `security`,
  `dig` — all present by default on supported macOS.
- If `--status` shows "primary ID : (none stored)" after `--setup`, the Keychain write or
  read failed. Open **Keychain Access** → login keychain → add a **password** item with
  name/service `pesu-wifi-primary`, account = your username, password = your login, then
  re-run `--setup` (it updates).

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| Nothing happens after joining Wi-Fi | Up to 60 s before launchd's next tick; or you weren't detected as offline (probe still returns `Success` — portal may be whitelisting it). Check `./pesu-wifi.sh --once`, then `./pesu-wifi.sh --status`. |
| Repeats "device limit" | You have a session/slot used elsewhere. Sign out on the other device or wait for it to time out; helper re-tries after 30 min (`--force` with `--once` to force now). Contact `itteam.rr@pes.edu` if it persists. |
| "no credentials saved" banner | Run `./pesu-wifi.sh --setup`. |
| Wrong password / rejected | Saved credential changed. Re-run `--setup`; if still failing, contact `itteam.rr@pes.edu`. |
| Logs | `~/pesu-wifi/state/pesu-wifi.log` (username + portal messages, password-scrubbed). |

## Manual sign-out note

The helper only signs **in**. To free a slot on this Mac's account: while signed in, open the
portal page and press its **Logout** button, or use the portal's own "Change Password"
account portal.

## Removal

```
cd ~/pesu-wifi
./pesu-wifi.sh --uninstall    # stops the agent, removes the plist and both Keychain items
cd ~ && rm -rf ~/pesu-wifi    # delete the folder itself
```

Nothing else on the system is touched.
